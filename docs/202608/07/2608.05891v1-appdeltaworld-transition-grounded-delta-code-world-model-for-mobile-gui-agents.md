## 摘要
移动GUI智能体可以通过像素感知和触摸操作来操作应用程序，这使它们成为收集和改进长时程移动交互策略的有前景的接口。然而，对于敏感应用和隐私关键操作，难以获取真实轨迹。同时，现有的模拟环境扩展成本高昂，而GUI世界模型仍存在生成不稳定、模态覆盖有限以及动作-转换逻辑不一致的问题。为应对这些限制，我们提出了AppDeltaWorld，这是一种转换接地的增量代码世界模型，它将下一个GUI预测为可达的代码更新，而非无约束的图像或文本描述。AppDeltaWorld在动作-转换约束下检索应用特定的 Level-1 HTML 参考，基于当前屏幕、动作、预测的下一屏幕文本和检索到的结构生成 Level-2 可执行HTML，并在浏览器渲染前将生成的视觉资产插入图像槽。作为世界模型，AppDeltaWorld 在 Code2World 评估下的 CMGUIBench-500 上实现了最高保真度，在结构布局和UI元素重建方面相较于仅图像和仅代码基线有明显提升。作为训练环境，AppDeltaWorld 支持过滤的闭环 SFT 数据构建，与公共监督结合，使 AppDeltaAgent 在 AndroidLens 上取得最先进性能，并在 MobileGym 和 MobileWorld 上持续获得提升。此外，基于世界模型的测试时强化学习实现了策略适应，并在不额外与真实应用交互的情况下展示了进一步改进。

## Abstract
Mobile GUI agents can operate apps through pixel perception and touch actions, making them a promising interface for collecting and improving long-horizon mobile interaction policies. However, real trajectories are difficult to obtain for sensitive apps and privacy-critical operations. At the same time, existing simulated environments are costly to scale up, and GUI world models still suffer from unstable generation, limited modality coverage, and inconsistent action-transition logic. To address these limitations, we propose AppDeltaWorld, a transition-grounded delta code world model that predicts the next GUI as a reachable code update rather than as an unconstrained image or text description. AppDeltaWorld retrieves app-specific Level-1 HTML references under an action-transition constraint, generates Level-2 executable HTML conditioned on the current screen, action, predicted next-screen text, and retrieved structure, and inserts generated visual assets into image slots before browser rendering. As a world model, AppDeltaWorld achieves the highest fidelity on CMGUIBench-500 under Code2World evaluation, with clear gains in structural layout and UI element reconstruction over image-only and code-only baselines. As a training environment, AppDeltaWorld supports filtered closed-loop SFT data construction that, when combined with public supervision, enables AppDeltaAgent to achieve state-of-the-art performance on AndroidLens and consistent gains on MobileGym and MobileWorld. Moreover, world-model-based test-time reinforcement learning enables policy adaptation and shows further improvements without additional interaction with real apps.

## 2. 方法论：AppDeltaWorld

### 2.1 核心思想

- **将GUO状态分解为两级HTML**：
  - **Level-1 HTML**：捕获可复用的页面结构与布局（结构性参照）；
  - **Level-2 HTML**：完成具体下一屏幕的可执行HTML（增量补全）。
- **转换接地的检索（Transition-Grounded Retrieval）**：利用应用特定的动作-转换索引约束目标检索，确保只能检索到动作可达的屏幕，对无效动作进行拒绝或低置信处理。
- **混合模态渲染流水线**：文本负责语义检索与转换接地，代码负责可执行布局与文本，扩散模型负责图像槽中的视觉资产合成，最终由浏览器渲染为截图。

### 2.2 关键技术细节与流程

**步骤一：转换接地的Level-1代码检索**
- 当前屏幕通过函数 `ϕ_text` 转化为结构化文本状态 `r_t = [f_t, d_t, ℓ_t, q_t, p_t]`（功能模板、屏幕描述、区域布局、槽模式、页面类型）。
- 离线索引阶段：每个历史屏幕存储为元组 `(r_i, h_i^(1), c_i^(0), c_i^(1))`，其中 `c_i^(0)` 为粗粒度功能类别（规则分类器得到），`c_i^(1)` 为细粒度簇（基于加权TF-IDF向量 `z_i = 0.45·z_layout + 0.25·z_dom + 0.20·z_sem + 0.10·z_slot` 的余弦相似度聚类）。
- 测试时：通过源查询 `q_t^src = [a, u, r_t, m_t]` 定位源簇 `c_t`；利用转换索引 `C_t+1 = T(c_t, α(m_t), κ(m_t))` 约束候选目标簇集合；基于目标查询 `q_t+1^tar` 在约束集合中选择最终Level-1 HTML参考 `h_i*^(1)`。

**步骤二：混合增量代码生成（式8）**
- 多模态生成器 `G_θ` 接收当前截图、结构化动作、预测的下一屏幕文本和检索到的Level-1参考HTML，生成Level-2 HTML：
  - `h_hat_t+1^(2) = G_θ(x_t, m_t, ŝ_t+1, h_i*^(1))`
- 这种"增量"方式避免每次从零生成整个界面，显著提高重复访问相似页面时的输出稳定性。

**步骤三：视觉资产合成与渲染（式7）**
- 从Level-2 HTML中提取图像槽的文本描述，使用Qwen-Image风格的文本到图像模型生成视觉资产并插入图像槽，最后用浏览器渲染为最终截图：
  - `x_hat_t+1 = R(I(G_θ(x_t, m_t, ŝ_t+1, h_i*^(1))))`
- 对于产品页面、视频应用等图像占主导的页面，扩散模型对保真度至关重要。

**步骤四：世界模型在环的SFT数据构建（Algorithm 1）**
- 使用GUI-Owl和OpenMobile的真实任务种子（初始截图+指令+应用元数据），由动作策略 `πη` 预测动作，世界模型生成下一状态，形成闭环合成轨迹。
- **过滤标准**（保证质量）：
  - 动作描述与坐标必须一致；
  - 不接受连续重复动作；
  - 最终步须为主观终止（非达最大步数）；
  - 排除空白屏幕或渲染失败轨迹。
- **关键统计**：数据通过率仅1/10，主要失败原因是任务进度丢失、模拟保真度下降和任务未按时完成。

- **合成数据效率偏低**：质量验证仅1/10通过，构建效率仍有明显瓶颈，这意味着在实际应用中，每生成10条轨迹只有1条可用，规模化扩展数据时需要付出较高的计算和过滤成本；论文虽展示了0K→28K的扩展收益，但未报告过滤失败样本的类型分布，也未能给出自动化质量判别器替代人工过滤的方案。

- **生成成本与推理开销偏大**：AppDeltaWorld平均输出token达8309.40，显著高于其他代码基线（Gemini-3-Flash为1818.40），且还需额外的文本到图像扩散模型合成视觉资产。若用于大规模RL训练，每步交互都会带来较高的生成延迟和推理计算代价，这限制了其在真实设备或低延迟场景下的在线应用。

- **跨设备跨版本泛化不足**：模型依赖应用特定的动作-转换索引与历史轨迹数据，面对未见过的新应用、新版本或非标准UI布局时，Level-1检索可能失效，转换索引也可能出现空候选；论文未设计零样本/少样本下的迁移实验来验证这种泛化边界。

- **评估主客观指标有待统一**：世界模型评估依赖LLM（Gemini-3-Flash）判定功能逻辑得分，且S_lay无法衡量跨分辨率的坐标一致性；对"保真度"的定义仍以部分语义/结构相似性为主，缺乏与真实用户感知或像素级FID等客观指标的交叉验证。

- **智能体差距未根本解决**：AppDeltaAgent在MobileGym上SR仅14.1%、MobileWorld上GUI-only SR仅14.9%，与专有模型（如Gemini 3.1 Pro在MobileGym上58.8%）仍存在数量级差距。论文证明了AppDeltaWorld能帮助改进自研基线，但尚不能说明其能替代真实环境去逼近最强agent的性能上限。

- **任务覆盖以常规操作为主**：当前轨迹数据大多来自购物、导航、视频等常见应用场景，对涉及复杂表单、多窗口、跨应用跳转、系统级权限交互等长尾任务覆盖不足，世界模型在这些场景下的转换一致性尚未得到验证。

## 9. 潜在风险与影响

- **合成数据的策略偏向风险**：若智能体长期在AppDeltaWorld构建的合成环境中训练，可能学到环境特有的捷径或过拟合到Level-1检索到的模板结构，而非真正的通用操作能力；尤其是数据过滤过程中丢弃了大量失败轨迹，可能使模型对"失败恢复"类策略学习不足。
- **对检索索引的强依赖**：转换接地的效果高度依赖历史屏幕的覆盖质量和动作-转换索引的完备性。在数据稀疏的应用上，检索可能返回不相关页面，导致增量代码生成继承错误的结构基准，最终屏幕与真实状态偏离。
- **扩散模型引入的视觉幻觉**：图像槽中的视觉资产由文本到图像模型生成，可能产生与真实产品不一致的图标、价格标签或商品图，从而影响agent对视觉信息的策略学习；论文未对这种渲染误差的传播效应进行量化分析。
- **LLM即评判者（LLM-as-Judge）的偏差**：使用Gemini-3-Flash作为S_ad、S_id和S_lay的评判者，存在对超长输出、格式化结果和特定生成风格的偏好风险，评判模型本身也可能在复杂功能逻辑判断上出错，而这些误差目前没有被校正或人检比例报告。
- **数据隐私与合规**：世界模型训练需大量真实GUI截图和操作轨迹，其中可能包含用户个人信息、账号页面和敏感交易界面；论文未讨论去标识化处理、数据使用许可以及在敏感应用上的部署约束。

## 10. 未来工作方向

- **低成本世界模型设计**：研究如何在保持高保真的前提下压缩输出token（如生成结构化diff而非完整HTML）、减少扩散模型调用频率（仅对内容密集型图像槽启用扩散），从而降低训练与推理开销，使其更适合大规模RL。
- **更强的转换一致性学习**：将无效动作的"拒绝行为"从外部规则约束（检索索引）内化为模型自身能力，通过构造负样本（无效动作-目标屏幕对）和对比学习，使生成器可以在无检索条件下直接判断动作可达性。
- **跨应用零样本泛化**：构建元索引或通用转换先验，探索在未见应用上借助页面结构相似性和动作语义相似性自动生成过渡索引，减少对应用特定离线数据的依赖。
- **自动数据质量过滤**：训练一个轻量的质量鉴别器（或利用小模型打分）替代当前依赖规则与人工的1/10过滤流程，提升合成数据生产效率，并将失败轨迹纳入训练以增强agent的错误恢复能力。
- **更细粒度的多模态融合**：在文本-代码-扩散的三级流水线上，探索让扩散模型直接感知布局约束（如元素边界框、文本框内容）的受控生成方式，以缓解视觉资产与布局结构之间的不一致。
- **真实场景闭环验证**：将AppDeltaWorld与真实设备回滚机制结合，构建"模拟训练→真实微调→模拟再训练"的迭代框架，量化合成训练向真实性能的迁移系数。

## 11. 总结与推荐

**一句话总结**：AppDeltaWorld通过"两级HTML + 转换接地检索 + 图像槽扩散"的增量代码生成范式，构造了一个高保真、可拒绝无效动作、混合模态的移动GUI世界模型，并以世界模型在环的SFT/RL实验证明了其作为训练环境的实用价值。

**推荐理由**：这篇论文在问题定义、方法设计和实验验证三个层面都保持了较高的完成度与诚实度：它没有回避合成数据的低通过率、聚类奖励的脆弱性、与专有大模型的性能差距等问题，而是将这些作为未来方向的起点。对于研究移动GUI智能体、世界模型、合成数据生成的学者和工程师而言，该文在"如何用代码增量更新替代自由生成"上的思路具有很强的启发性和可复用性。建议在阅读时重点关注其转换索引的构建细节、消融实验的设计逻辑，以及其世界模型在RL训练中的实际作用机制。
