## 摘要
当前视频世界模型在多玩家环境中存在困难，因为它们将世界状态与视角相关的视觉潜变量纠缠在一起，导致冗余计算、视角不一致和可扩展性差。我们提出MAS（具有权威共享状态的多玩家世界模型）来解决这一限制。受多玩家游戏架构的启发，MAS将世界动态与视角渲染分离。一个习得的逻辑引擎根据联合动作推进全局权威的类型化状态，无需任何手写转移函数，并作为唯一的循环记忆和同步参考。从这个共享状态出发，一个习得的渲染引擎按需为任何请求的视角生成独立且一致的视图。这种显式解耦使得MAS在匹配的多玩家贪吃蛇基准测试中，与最先进的多视角基线相比，实现了更高的状态准确性和更低的跨视角不一致性。它推进了包含1,024个并发玩家、10,000个循环步骤的预测世界。我们的结果表明，显式的权威状态建模为可扩展且一致的多智能体世界模拟提供了实用基础。

## Abstract
Current video world models struggle in multiplayer environments because they entangle world state with view-dependent visual latents, leading to redundant compute, view inconsistencies, and poor scalability. We propose MAS (Multiplayer world models with Authoritative Shared State) to resolve this limitation. Inspired by multiplayer game architectures, MAS disentangles world dynamics and view rendering. A learned Logic Engine advances a global, authoritative typed state from joint actions without any hand-written transition function, acting as the sole recurrent memory and synchronization reference. From this shared state, a learned Rendering Engine generates independent and consistent views for any requested camera on demand. This explicit disentangling allows MAS to achieve superior state accuracy and lower cross-view inconsistency compared to state-of-the-art multi-view baselines on a matched multiplayer Snake benchmark. It advances predicted worlds with 1,024 concurrent players for 10,000 recurrent steps. Our results show that explicit, authoritative state modeling provides a practical foundation for scalable and consistent multi-agent world simulation.

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：交互式视频世界模型（如 GameNGen、Oasis、DIAMOND、Genie、WHAM 等）通过像素或视觉潜变量作为循环记忆载体来预测下一帧观测，在单玩家场景下表现出色。但在多玩家环境中，每个视角都需要独立的循环历史，导致三个固有问题：
  - **冗余计算**：同一共享世界内容被每个视角重复编码，仿真成本随视角数量线性增长；
  - **视角不一致**：各视角独立的视觉历史对同一实体的状态可能产生分歧；
  - **可扩展性差**：难以支撑大量并发玩家与观众视角。
- **核心问题**：现有视频世界模型将“世界状态”与“视角相关的视觉表示”纠缠在一起，缺乏一个**属于世界本身而非属于任何相机**的循环状态。
- **核心含义（MASS 的解法）**：借鉴多玩家游戏的权威服务器架构，将“世界动态模拟”与“视角渲染”解耦。由一个习得的**逻辑引擎（Logic Engine）**推进全局权威类型化状态，作为唯一的循环记忆和同步参考；再由一个习得的**渲染引擎（Rendering Engine）**从该共享状态按需生成任意相机的视图。这样世界每 tick 只推进一次，仿真成本与渲染视角数无关。

### 2. 方法论：核心思想、关键技术细节与算法流程

#### 2.1 总体架构

MASS 的完整流程（Algorithm 1）如下：
1. 将当前权威状态 `s_t` 按模式（schema）序列化为结构化记录；
2. 对每条记录构造局部上下文窗口 `c_i,t`（包含邻近单元、玩家动作、外生输入）；
3. 逻辑引擎（单解码器 Transformer）逐记录预测下一状态的 token，经模式约束解码与确定性选择器组装为 `s_{t+1}`；
4. 将 `s_{t+1}` 作为唯一循环输入、同步对象和所有视角的渲染来源；
5. 渲染引擎对每个请求的相机执行投影（`P_i`），由残差 U-Net 生成 RGB 帧。

#### 2.2 世界状态分词器

- **模式（Schema）**：每个游戏通过声明式文件定义实体类型、字段和实例数量，例如 `(kind_j, fields_j, count_j)`。
- **状态表示**：每个 tick 的世界状态为所有实体记录的集合 `s_t = {ρ_1,...,ρ_{K_g}}`，每条记录为类型化字段的有序集合。
- **序列化与解序列化**：类型标签、坐标、可选值、列表等均以固定位置写入 token 序列，可无损还原。规范填充和类型标签范围使任意合法状态映射为固定宽度序列，无需为每个游戏修改架构。
- 在贪吃蛇实验中，一个 tick 实例化 5,121 条记录：1 条全局记录、1,024 条蛇记录、4,096 条食物桶记录。

#### 2.3 逻辑引擎

- 采用**Decoder-only 因果 Transformer**（宽度 256、6 层、8 头、MLP 扩张率 4）；
- 世界级转移函数：`s_{t+1} = F_θ(s_t, a_t, e_t)`；
- 分布因式分解：`p_θ(s_{t+1}|s_t,a_t,e_t) ≈ Π_i Π_j p_θ(y_{i,j}^{t+1}|u_i^t, y_{i,<j}^{t+1})`，每条记录只依赖自身前缀和上下文窗口，自注意力限制在记录序列内部，记录之间无注意力，从而支持大规模实体；
- **模式派生掩码**确保每个输出位置只产生合法取值；确定性选择器强制跨记录约束（如排序、唯一性）；
- 训练采用教师强制（teacher forcing）的 token 交叉熵，推理时为贪心自回归解码，**不使用任何原生游戏转移代码或规则修复**。

#### 2.4 渲染引擎

- 对相机 i 的投影 `P_i(s_t)` 将可见单元的占用、语义角色、所有权、深度与几何信息写入 16 通道张量；
- 残差 U-Net 将该张量与相机参数映射为 RGB 帧：`ô_t = R_ϕ(P_i(ŝ_t), κ_i)`；
- **所有视角读取同一个共享状态**，因此视图在构造上保证一致；渲染器无需 RGB 历史，相机可随时增删/移动/升级，不影响世界转移；
- 渲染器的子模块作为独立可训练组件，与逻辑引擎分开训练与评估。

#### 2.5 服务器与客户端逻辑

- **权威状态**：无论预测准确度如何，服务器发布的版本化状态是唯一被所有客户端采纳的版本；
- 每 tick 服务器开销为 `T_server = T_logic(N) + C·t_sync(S)`，即世界转移只执行一次，分发成本随客户端数线性增加，渲染在客户端本地执行；
- **客户端预测**：当服务器更新中断时，客户端使用同一逻辑引擎从最新权威状态本地推进，使用自身动作并将其他玩家动作置为 no-op；服务器恢复后以版本化状态直接替换推测状态，无需额外校正网络。

### 6. 主要结论与发现

1. **解耦有效**：将世界动态与视图合成分离后，MASS 在匹配贪吃蛇基准上 6/7 项指标领先：LPIPS 0.098（最优）、Parser 恢复 0.764（为最强视频基线的 5 倍以上）、X-view 不一致 0.000（构造上保证一致）。
2. **密集载体不保留实体**：B-UN 的 LPIPS 虽接近（0.123），但解析器恢复为 0，证明像素级相似不代表世界状态可恢复——显式类型化载体是实体身份与位置连续性的关键。
3. **同一架构多游戏泛化**：仅通过声明式 schema 改变词表、嵌入与权重，MASS 应用于 8 个游戏，5 个游戏 PSNR 超 32 dB，对象 PSNR 大多超 27.5 dB。
4. **长期可扩展**：支持 1,024 实体推进 10,000 tick；H=4,096 时玩家名册完整、零结构性无效步、状态多样性保持。
5. **客户端预测可行**：更新中断 k=8 tick 内本玩家零位移；oracle 联合输入下与服务器完全一致，衰减源于远程动作未知而非转移误差。
6. **误差可定位**：通过 SRSC 四轴分解可分离逻辑引擎与渲染引擎的贡献；渲染器在真实状态下保持稳定（Renderer-GT 无单调下降），性能衰减主要来自动态预测。

### 7. 方法优点与设计亮点

- **架构级一致性保证**：所有视角解码自同一状态，跨视角不一致性为 0 而非靠后处理近似；
- **计算复杂度与视角数解耦**：世界转移每 tick 只运行一次，渲染按需执行，符合传统游戏服务器的效率模型；
- **可解释、可评估**：类型化状态可直接度量实体持久性、位置精度、结构合法性，无需生成一帧即可定位错误；
- **声明式 schema 泛化**：同一 Transformer 架构通过 schema 换游戏，无架构修改，新游戏集成速度快（论文称一晚集成 3 个游戏）；
- **滚动中无需规则修复**：运动、碰撞、生长等全部为学习结果，无手写转移函数；
- **工程实现细致**：记录级批处理、上下文窗口限制注意力范围、模式掩码保证结构有效性、客户端版本同步与本地预测机制完整。

### 8. 不足与局限

- **环境维度有限**：所有实验均为 2D 或 2.5D 环境，未验证 3D 场景中的可扩展性；论文将 3D 扩展列为未来方向；
- **实体交互复杂度有限**：Snake、Breakout、Tile Merger 等交互模式相对简单，未涉及复杂物体交互、物理规律或长程依赖语义；
- **端到端跨游戏对比不足**：跨游戏实验多在状态层面（逻辑）或单独渲染质量层面，缺少完整端到端对比（预测状态+渲染）；
- **基线覆盖不全**：未与现代视觉潜变量世界模型（如 IRIS/DreamerV3 风格）或更大的多智能体生成模型（如 WanToFight 等）直接比较；MultiWorld 参数规模差异悬殊；
- **SRSC 判定器依赖单一模型**：Qwen3.5-27B 的评估可能存在风格偏向，且采样为固定 seed+greedy，未评测置信度校准；
- **算力细节不透明**：未报告 GPU 数量、总训练时长与能耗，可复现性受影响；
- **训练步数与数据规模偏小**：匹配 Snake 仅 20,000 步更新，128 个训练 episode，跨游戏数据集也较小（如 Tile Merger 仅约 5.7k 转换），真实复杂游戏中的表现仍待验证；
- **客户端预测假设较强**：不明确未来食物生成等外生输入时，非本玩家区域的预测会退化（协议为 no-op），仅适用于短中断场景。
